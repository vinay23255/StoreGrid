# StoreGrid NLP Service

> High-throughput, deterministic rule-based retail customer feedback classification service built with FastAPI and Python 3.12.

StoreGrid NLP categorizes operational store feedback into actionable departments (inventory, billing, frontline staff, product freshness, and hardware maintenance) while seamlessly understanding English and **Telugu-English code-mixed** retail expressions.

## Supported Categories

| Category | Description | Sample Expressions (English & Telugu-English) |
|---|---|---|
| `STOCK_SHORTAGE` | Out-of-stock items, empty shelves, unavailable inventory | *"out of stock"*, *"empty shelves"*, *"milk stock ledu"*, *"shelves khali ga unnai"* |
| `BILLING_DELAY` | Long queues, slow billing counters, payment terminal delays | *"slow billing"*, *"queue is too long"*, *"billing chala slow ga undi"*, *"line chala peddaga undi"* |
| `STAFF_BEHAVIOUR` | Staff attitude, conduct, customer service quality | *"cashier was rude"*, *"unhelpful staff"*, *"staff rude ga matladaru"*, *"mariyada ledu"* |
| `PRODUCT_QUALITY` | Expired, spoiled, stale, or damaged items | *"expired product"*, *"stale bread"*, *"curd stale ga undi"*, *"milk expire aipoyindi"* |
| `EQUIPMENT_FAILURE` | Faulty POS machines, broken scanners, AC or freezer breakdown | *"scanner broken"*, *"pos not working"*, *"ac pani cheyatledu"*, *"refrigerator cooling ledu"* |
| `OTHER` | Legitimate feedback outside operational categories (parking, timings, ambience) | *"no parking space"*, *"store timings"*, *"parking kashtam ga undi"*, *"great discounts"* |
| `NEEDS_REVIEW` | Ambiguous, empty, unrecognized, or conflicting multi-intent feedback | *""*, *"ok"*, *"something happened"*, *"cashier was rude and milk was expired"* |

## Architecture & Classification Logic

The service follows a **modular architecture**, keeping data validation (`schemas.py`), rule evaluation (`classifier.py`), and HTTP transport (`main.py`) strictly decoupled.

### Text Normalization
1. **Preservation**: The incoming text is preserved bit-for-bit in `originalText`.
2. **Cleaned Text**: A normalized representation (`cleanedText`) is generated by stripping leading/trailing whitespace, converting all characters to lowercase, and collapsing consecutive spaces, tabs, and newlines into single spaces.

### Boundary-Aware Matching
To prevent false-positive substring collisions (e.g., ensuring "stocking" does not trigger "stock", or "routine" does not trigger "rotten"), rules utilize regular expression word boundaries (`\b`).

### Transparent Confidence Scoring
The service **does not invent artificial machine learning probabilities**. The confidence score represents deterministic rule strength:
- **Multi-Word Phrase Matches**: Weight between `0.85` and `0.90` (e.g., *"billing chala slow ga undi"*, *"pos not working"*).
- **Distinct Keyword Matches**: Weight between `0.70` and `0.75` (e.g., *"disrespectful"*, *"expired"*).
- **Reinforcement Bonus**: If multiple distinct terms match within the same category (e.g. *"out of stock"* + *"empty shelves"*), `+0.05` is added per additional matched term, capped at `0.95`.
- **Threshold**: Categories with scores `< 0.60` are routed to `NEEDS_REVIEW`.
- **Empty / Ambiguous / Gibberish**: Assigned `NEEDS_REVIEW` with `confidence = 0.0` and `needsReview = true`.

### Conservative Conflict Resolution
When feedback spans multiple conflicting operational categories with strong signals (e.g., a customer complaining that *"the cashier was rude and the milk was expired"*):
- Rather than making an arbitrary guess, the engine routes the item to `NEEDS_REVIEW`.
- Confidence is set to `0.40` (the conflict score).
- `needsReview` is set to `true`.
- `matchedTerms` aggregates all matched terms from the colliding categories, allowing human store managers to address both departments.

### 3. Classify Feedback (`POST /classify`)
Classifies customer feedback text into operational retail categories.

- **Request Headers**: `Content-Type: application/json`
- **Request Body**:
  | Field | Type | Required | Description |
  |---|---|---|---|
  | `feedbackId` | `string` | Yes | Unique identifier for the feedback record. |
  | `storeId` | `string` | Yes | Store location or branch code. |
  | `text` | `string` | Yes | Raw customer feedback text. |
  | `sourceType` | `string` | No (default: `"review"`) | Feedback source (e.g. `kiosk`, `mobile_app`, `survey`). |
  | `language` | `string` | No (default: `"en"`) | Language hint (e.g. `en`, `te-en`). |
  | `createdAt` | `string` | No | ISO timestamp when feedback was generated. |

- **Response Body** (`200 OK`):
  | Field | Type | Description |
  |---|---|---|
  | `feedbackId` | `string` | Echoed feedback ID. |
  | `storeId` | `string` | Echoed store ID. |
  | `originalText` | `string` | Exact, unmodified original input text. |
  | `cleanedText` | `string` | Lowercase, whitespace-normalized string. |
  | `category` | `string` | One of the 7 supported categories. |
  | `confidence` | `float` | Deterministic rule strength score (`0.0` - `0.95`). |
  | `needsReview` | `boolean` | `true` if human attention is required, `false` otherwise. |
  | `matchedTerms` | `array[string]`| List of matched rule phrases or keywords. |

- **Error Codes**:
  - `422 Unprocessable Entity`: Returned when required fields (`feedbackId`, `storeId`, or `text`) are missing or payload is malformed.

## Teammate Integration Guide (Node.js / Express Backend)

This section provides complete instructions for integrating this NLP service with Vinay's Node.js/Express backend.

### Environment Variable Configuration

In the Node.js project (`.env` file or environment variables), configure the URL pointing to the NLP service:

```bash
# .env in Node.js project
NLP_SERVICE_URL=http://127.0.0.1:8000
```

In your Node.js configuration module:
```javascript
const NLP_SERVICE_URL = process.env.NLP_SERVICE_URL || 'http://127.0.0.1:8000';
```

### Network & Container Addressing Note
> **Important**: `127.0.0.1` refers to the local loopback of the **current machine or container**.
> - **Same Host Machine**: If both Node.js and the Python FastAPI service run directly on the same host (e.g. during local development), `http://127.0.0.1:8000` works as expected.
> - **Docker Desktop**: If the Node.js app runs inside a Docker container while the Python service runs on the host, configure `NLP_SERVICE_URL=http://host.docker.internal:8000`.
> - **Docker Compose / Kubernetes**: If both services run in separate containers within a shared network, set `NLP_SERVICE_URL` to the service DNS name (e.g. `http://storegrid-nlp:8000`).

### CORS Architecture & Security Consideration
- **Why CORS is NOT enabled on this service**: In this architecture, customer web browsers call the Express backend. The Express backend in turn makes a **server-to-server** HTTP request to the Python NLP service.
- Browser CORS restrictions only apply to browser-initiated cross-origin requests (`fetch` / `XMLHttpRequest` in the browser). Server-to-server HTTP calls in Node.js do not execute in a browser sandbox and are not subject to CORS policies.
- Therefore, adding permissive CORS (`allow_origins=["*"]`) to the internal NLP service is unnecessary and would introduce an unnecessary security exposure. All public client traffic should continue routing through Vinay's Express gateway.

### Sample Node.js `fetch` Request

Using modern Node.js (Node 18+ native `fetch`):

```javascript
// services/nlpService.js
const NLP_SERVICE_URL = process.env.NLP_SERVICE_URL || 'http://127.0.0.1:8000';

/**
 * Sends customer feedback to StoreGrid NLP classification API.
 * @param {Object} feedback
 * @param {string} feedback.feedbackId - Unique feedback identifier
 * @param {string} feedback.storeId - Store location code
 * @param {string} feedback.text - Raw customer feedback
 * @param {string} [feedback.sourceType="review"] - Source (kiosk, app, etc.)
 * @param {string} [feedback.language="en"] - Language hint
 * @param {string} [feedback.createdAt] - ISO timestamp
 * @returns {Promise<Object>} Classification result
 */
async function classifyFeedback(feedback) {
  const controller = new AbortController();
  const timeoutId = setTimeout(() => controller.abort(), 3000); // 3-second SLA timeout

  try {
    const response = await fetch(`${NLP_SERVICE_URL}/classify`, {
      method: 'POST',
      headers: {
        'Content-Type': 'application/json',
      },
      body: JSON.stringify(feedback),
      signal: controller.signal,
    });

    clearTimeout(timeoutId);

    if (!response.ok) {
      const errorBody = await response.text();
      throw new Error(`NLP Service returned HTTP ${response.status}: ${errorBody}`);
    }

    const data = await response.json();
    return data;
  } catch (error) {
    clearTimeout(timeoutId);

    // Timeout or network error handling
    if (error.name === 'AbortError') {
      console.error(`[NLP] Request timed out for feedback ${feedback.feedbackId}`);
    } else {
      console.error(`[NLP] Request failed for feedback ${feedback.feedbackId}:`, error.message);
    }

    // Conservative Fallback: route unclassified feedback to NEEDS_REVIEW
    return {
      feedbackId: feedback.feedbackId,
      storeId: feedback.storeId,
      originalText: feedback.text,
      cleanedText: (feedback.text || '').trim().toLowerCase(),
      category: 'NEEDS_REVIEW',
      confidence: 0.0,
      needsReview: true,
      matchedTerms: [],
      error: error.message,
    };
  }
}

module.exports = { classifyFeedback };
```

### Express Controller Integration Example

```javascript
// routes/feedback.js
const express = require('express');
const router = express.Router();
const { classifyFeedback } = require('../services/nlpService');

router.post('/feedback', async (req, res) => {
  const { feedbackId, storeId, text, sourceType, language } = req.body;

  if (!feedbackId || !storeId || !text) {
    return res.status(400).json({ error: 'Missing required fields: feedbackId, storeId, text' });
  }

  // 1. Classify with NLP microservice
  const classification = await classifyFeedback({
    feedbackId,
    storeId,
    text,
    sourceType: sourceType || 'mobile_app',
    language: language || 'en',
    createdAt: new Date().toISOString(),
  });

  // 2. Actionable operational triage
  if (classification.needsReview) {
    console.log(`[StoreGrid] Queued feedback ${feedbackId} for store manager manual review.`);
  } else if (classification.category === 'STOCK_SHORTAGE') {
    console.log(`[StoreGrid] Alerting inventory team for store ${storeId}: ${classification.matchedTerms}`);
  }

  // 3. Return stored record and classification to client
  return res.status(201).json({
    status: 'success',
    data: classification,
  });
});

module.exports = router;
```

### Timeout & Error Handling Guidance
1. **Timeout SLA**: It is recommended to use an explicit timeout of **2,000–3,000 ms** using `AbortController` or axios `timeout`. Since the rule-based Python classifier runs in < 5 ms, any delay indicates network issues or service downtime.
2. **Graceful Fallback**: If the NLP service is unreachable (network error or timeout), the Node.js backend should not crash or fail the customer's submission. Instead, record the feedback with `category: "NEEDS_REVIEW"` and `needsReview: true`.
3. **Validation Errors (`422`)**: If the Express backend sends a request missing `feedbackId`, `storeId`, or `text`, FastAPI responds with `422 Unprocessable Entity`. Validate these fields in Express before dispatching.

## Operational Limitations

1. **Rule-Based Specificity**: The engine matches known high-frequency operational keywords and phrases. Severe misspellings (e.g. *"stck ldu"*) or novel regional dialect slang not yet registered in `classifier.py` will default conservatively to `NEEDS_REVIEW`.
2. **Multi-Intent Feedback**: If a customer provides a lengthy paragraph covering multiple issues simultaneously (e.g. staff conduct, out of stock items, and billing queues), the service marks the item as `NEEDS_REVIEW` with `confidence = 0.40` so that human supervisors can appropriately route sub-tasks.
3. **Absence of Black-Box Probabilities**: Confidence numbers reflect explicit rule matches and reinforcements rather than ML probabilities.
4. **Zero Paid API Overhead**: Does not call paid external LLM APIs (OpenAI, Anthropic, Google Gemini), guaranteeing sub-millisecond latency, zero token costs, and 100% data privacy.
